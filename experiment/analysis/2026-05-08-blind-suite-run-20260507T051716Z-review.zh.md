## 评分方法

评分采用 blind-suite 的 1-5 分制：

- `证据纪律`：结论是否绑定 allowed source 中的指标、报告语句或实验结果。
- `正确诊断`：答案是否命中 hidden reviewer key。
- `不过度声称`：是否避开 known bad conclusions。
- `失败归因 / 最小性`：下一步是否针对源文件支持的 failure mode，是否避免直接扩展到大系统模块。
- `可证伪性`：在适用任务中，是否给出清楚的成功或反证条件。
- `trace 质量`：`trace.md` 是否能审计出从证据到结论的路径。

关键原则：hidden reviewer key 是预期答案边界。某个条件即使写得更完整，
如果引入了当前 probe 的 allowed source 不支持的机制归因，也要扣分。

## 跨条件发现

1. `research-discipline` 有价值，但会过度导向机制解释。  
   它提升 prototype/prior 类任务，但在 Q5 这类只允许 Q5 证据的 probe 中，
   会诱导模型提出当前证据还支撑不了的机制归因。

2. `structured-trace` 明显提升可审计性。  
   它赢下 Q3/Q4/Q6/next-prior，因为它更清楚地暴露 rejected conclusions
   和 uncertainty。但 trace 质量优势部分来自 condition 本身，不能直接等同于诊断更好。

3. 当源文档已经很明确时，`naive` 仍然有竞争力。  
   Q5 和 adversarial-scaling 中，public source 已经给出强答案，额外引导反而可能制造过度归因。

4. 当前 blind suite 更多测试 evidence discipline，而不是开放式 discovery。  
   很多 public source 文档已经包含 “does not validate” 或 current-result summary，
   与 hidden key 很接近。

## 盲测有效性问题

1. public sources 过于答案化。  
   Q1/Q2/Q3/Q4/Q5/Q6 都包含明确结果和 limitation section。适合测试 careful reading，
   但不够适合测试独立科学推理。

2. Q7 source mismatch 会影响评分。  
   旧的 `experiment/probes/q7-generalization.md` 列了 audit source，但 blind-suite run
   的 source list 只有 Q7 doc/json。hidden key 对 next priors 的部分期望依赖 audit-derived priors，
   因此 Q7 的 prior scoring 要带这个 caveat。

3. condition label 对 agent 可见。  
   prompt 包含 `# Condition: Naive` 等。如果目标是测试不同 prompt 条件，这可以接受；
   如果目标是 model-blind condition test，就不够严格。

4. trace scoring 与 condition 不独立。  
   `structured-trace` 明确要求更好的 trace，因此在 trace quality 上天然占优。
   判断 winner 时应把 trace quality 和 diagnosis quality 分开看。

## 建议

1. 暂时保留三种条件。  
   它们暴露不同 failure mode：naive 容易简化下一步；research-discipline 可能过度导向机制；
   structured-trace 可能高估过程格式。

2. 为更难的未来 probe 创建 stripped source packets。  
   从 allowed source 中移除 “Current answer”、“What this does not validate”、
   downstream synthesis 等接近答案的段落，只保留方法、指标和原始结果。

3. 增加 adversarial source conflicts。  
   放入一个诱人的但不被支持的模块建议，以及一个看起来很好但不决定性的指标，
   测试 agent 能否同时抵抗这两类诱导。

4. 区分 reviewer-blind 和 model-blind。  
   如果想让模型不知道自己属于哪个 condition，就隐藏 condition 名称，用中性文件名，
   但内部仍改变 instruction block。

5. 校准 hidden key 与 allowed sources。  
   如果 hidden key 期待 audit-derived priors，allowed source list 就应包含 audit；
   否则该维度评分应降低权重。
