## Scoring Method

Scores use the blind-suite 1-5 rubric:

- `Evidence discipline`: claims are tied to allowed-source metrics or report statements.
- `Correct diagnosis`: the answer matches the hidden reviewer key.
- `Non-overclaiming`: the answer avoids known bad conclusions.
- `Failure attribution / minimality`: the next step targets the source-supported failure mode and avoids broad modules.
- `Falsifiability`: the answer gives a clear success or disconfirmation condition, where relevant.
- `Trace quality`: `trace.md` preserves an auditable path from evidence to conclusion.

Important: the hidden reviewer key is the primary expected-answer boundary. A
condition can score high on style and still lose points if it imports a mechanism
not supported by that probe's allowed source files.

## Cross-Condition Findings

1. `research-discipline` is useful but can over-steer.
   It improves prototype/prior tasks but sometimes encourages mechanism
   proposals beyond the current probe's allowed evidence, as in Q5.

2. `structured-trace` improves auditability.
   It wins Q3/Q4/Q6/next-prior because it surfaces rejected conclusions and
   uncertainty. However, its trace-quality advantage is partly baked into the
   condition and should not be mistaken for better diagnosis in every case.

3. `naive` remains competitive when source documents are explicit.
   It wins Q5 and adversarial-scaling because the public source already states
   the answer and extra guidance creates room for over-attribution.

4. The blind suite mostly tests evidence discipline, not open discovery.
   Many public source documents include "does not validate" or current-result
   summaries that are close to the hidden key.

## Blind-Test Validity Concerns

1. Public sources are often answer-like.
   Q1/Q2/Q3/Q4/Q5/Q6 all contain explicit result and limitation sections. This
   is acceptable for testing careful reading, but weak for testing independent
   scientific inference.

2. Q7 source mismatch affects grading.
   The older `experiment/probes/q7-generalization.md` lists an audit source, but
   the blind-suite run source list only includes Q7 doc/json. Hidden-key
   expectations about next priors partly depend on audit-derived priors, so Q7
   prior scoring should be read with this caveat.

3. Condition labels are visible to the agent.
   Prompts include `# Condition: Naive` etc. This is fine if the goal is
   condition-specific prompt testing, but it is not a condition-blind test from
   the model's perspective.

4. Trace scoring is not independent of condition.
   `structured-trace` explicitly asks for a better trace, so it has a built-in
   advantage on trace quality. Winner decisions should separate trace quality
   from diagnosis quality.

## Recommendations

1. Keep all three conditions for now.
   They reveal different failure modes: naive over-simplifies next steps,
   research-discipline can over-steer mechanisms, structured-trace can overvalue
   process form.

2. For harder future probes, create stripped source packets.
   Remove "Current answer", "What this does not validate", and downstream
   synthesis sections from allowed sources. Keep metrics and method only.

3. Add adversarial source conflicts.
   Include one tempting but unsupported module proposal and one metric that
   looks good but is not decisive, then test whether the agent resists both.

4. Separate reviewer-blind and model-blind designs.
   If model-blind condition testing matters, hide condition names and use neutral
   filenames while still varying the instruction block.

5. Calibrate hidden keys against allowed sources.
   If a hidden key expects audit-derived priors, the allowed source list should
   include the audit; otherwise score that dimension lower weight.
